The Envoy REST API gives you programmatic access to every resource on the platform — workspaces, users, integrations, webhooks, and reports. All requests are made over HTTPS and return JSON. Whether you are automating workspace provisioning, syncing user data, or building a custom integration, the API provides a consistent, predictable interface you can rely on.

<Note>
  **Base URL**

  All API requests must be made to:

  ```
  https://api.envoy.com/v1
  ```

  Every endpoint in this reference is relative to this base URL.
</Note>

## API Versioning

The current stable version of the Envoy API is **v1**, reflected in the base URL. When breaking changes are introduced, a new version is released under a new path (for example, `/v2`). The previous version remains available for a deprecation window that is communicated via email and the changelog. Non-breaking additions — such as new optional fields or new endpoints — may be added to the current version at any time.

## Rate Limits

Envoy enforces per-minute rate limits based on your plan. If you exceed your limit, the API returns `429 Too Many Requests`. The response includes a `Retry-After` header indicating how many seconds to wait before retrying.

| Plan       | Requests per minute |
|------------|---------------------|
| Growth     | 1,000               |
| Enterprise | 5,000               |

<Tip>
  If you are approaching rate limits, consider batching requests or caching responses on your end. Enterprise customers can contact support to discuss higher limits for specific use cases.
</Tip>

## Response Format

Every API response uses the same JSON envelope structure, giving you a consistent shape to parse regardless of the endpoint.

| Field   | Type   | Description                                                          |
|---------|--------|----------------------------------------------------------------------|
| `data`  | object or array | The primary payload — a single resource or a list of resources. |
| `meta`  | object | Pagination metadata, present on list endpoints.                      |
| `error` | object | Present only on error responses; contains `code` and `message`.     |

A successful single-resource response looks like this:

```json
{
  "data": {
    "id": "ws_01HXZ3K9P",
    "name": "Engineering"
  }
}
```

An error response looks like this:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing API key."
  }
}
```

## Pagination

List endpoints use **cursor-based pagination**. Rather than offset pages, each response returns a `next_cursor` value you pass as a query parameter in your next request. This approach is stable even when records are added or removed between requests.

**Query parameters:**

| Parameter     | Type    | Description                                              |
|---------------|---------|----------------------------------------------------------|
| `limit`       | integer | Number of records to return per page. Default is `20`, max is `100`. |
| `next_cursor` | string  | Cursor returned by the previous response. Omit on the first request. |

**Example paginated response:**

```json
{
  "data": [...],
  "meta": {
    "total": 42,
    "limit": 20,
    "next_cursor": "cur_01HXZ"
  }
}
```

When `next_cursor` is `null` or absent from the `meta` object, you have reached the last page.
