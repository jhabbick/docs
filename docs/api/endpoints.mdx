The Envoy API exposes endpoints for managing the core resources on your account: workspaces, users, integrations, and reports. Each section below documents the available operations, the parameters they accept, and the shape of their responses. All requests require a valid Bearer token in the `Authorization` header — see the [Authentication guide](/docs/api/authentication) if you have not set that up yet.

---

## Workspaces

Workspaces are the top-level organizational unit in Envoy. You can list all workspaces your API key has access to and create new ones.

### GET /workspaces

Retrieve a paginated list of all workspaces accessible to your API key.

```bash
curl https://api.envoy.com/v1/workspaces \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response:**

```json
{
  "data": [
    {
      "id": "ws_01HXZ3K9P",
      "name": "Engineering",
      "slug": "engineering",
      "visibility": "private",
      "member_count": 12,
      "created_at": "2024-06-01T10:00:00Z"
    }
  ],
  "meta": {
    "total": 1,
    "limit": 20,
    "next_cursor": null
  }
}
```

### POST /workspaces

Create a new workspace. You must have a `write` or `admin`-scoped API key to use this endpoint.

**Request parameters:**

<ParamField body="name" type="string" required>
  The display name for the workspace. Must be between 1 and 128 characters.
</ParamField>

<ParamField body="slug" type="string" required>
  A URL-safe identifier for the workspace. Must be lowercase, contain only letters, numbers, and hyphens, and be unique within your account.
</ParamField>

<ParamField body="visibility" type="string" default="private">
  Controls who can discover the workspace. Accepted values are `"private"` (invite-only) or `"public"` (visible to all members of the account).
</ParamField>

**Example request:**

```bash
curl -X POST https://api.envoy.com/v1/workspaces \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Engineering", "slug": "engineering", "visibility": "private"}'
```

**Example response:**

```json
{
  "data": {
    "id": "ws_01HXZ3K9P",
    "name": "Engineering",
    "slug": "engineering",
    "visibility": "private",
    "member_count": 1,
    "created_at": "2024-06-01T10:00:00Z"
  }
}
```

**Response fields:**

<ResponseField name="data" type="object">
  The newly created workspace object.

  <Expandable title="data fields">
    <ResponseField name="id" type="string">
      The unique identifier for the workspace, prefixed with `ws_`.
    </ResponseField>
    <ResponseField name="name" type="string">
      The display name of the workspace as provided in the request.
    </ResponseField>
    <ResponseField name="slug" type="string">
      The URL-safe identifier for the workspace.
    </ResponseField>
    <ResponseField name="visibility" type="string">
      Either `"private"` or `"public"`.
    </ResponseField>
    <ResponseField name="member_count" type="integer">
      The number of members currently in the workspace. Starts at `1` (the creator).
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the workspace was created.
    </ResponseField>
  </Expandable>
</ResponseField>

## Users

The Users endpoints let you list members of a workspace, invite new users, and remove existing ones. User operations are scoped to a specific workspace via the `workspace_id` parameter.

### GET /users

Retrieve a paginated list of users in a workspace.

**Query parameters:**

<ParamField query="workspace_id" type="string" required>
  The ID of the workspace whose members you want to list.
</ParamField>

<ParamField query="role" type="string">
  Filter results by role. Accepted values: `"owner"`, `"admin"`, `"member"`, `"guest"`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Number of records to return. Maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned by a previous response. Omit on the first request.
</ParamField>

```bash
curl "https://api.envoy.com/v1/users?workspace_id=ws_01HXZ3K9P&role=member&limit=20" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response:**

```json
{
  "data": [
    {
      "id": "usr_09ABZ1M2Q",
      "email": "alex@example.com",
      "name": "Alex Rivera",
      "role": "member",
      "joined_at": "2024-06-02T08:30:00Z"
    }
  ],
  "meta": {
    "total": 12,
    "limit": 20,
    "next_cursor": null
  }
}
```

### POST /users

Invite a user to a workspace by email address. If the email address is not associated with an existing Envoy account, an invitation email is sent automatically.

**Request parameters:**

<ParamField body="workspace_id" type="string" required>
  The ID of the workspace to invite the user into.
</ParamField>

<ParamField body="email" type="string" required>
  The email address of the person to invite.
</ParamField>

<ParamField body="role" type="string" default="member">
  The role to assign to the invited user. Accepted values: `"admin"`, `"member"`, `"guest"`.
</ParamField>

```bash
curl -X POST https://api.envoy.com/v1/users \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"workspace_id": "ws_01HXZ3K9P", "email": "alex@example.com", "role": "member"}'
```

**Example response:**

```json
{
  "data": {
    "id": "usr_09ABZ1M2Q",
    "email": "alex@example.com",
    "role": "member",
    "status": "invited",
    "invited_at": "2024-06-03T09:00:00Z"
  }
}
```

### DELETE /users/:id

Remove a user from a workspace. The user loses access immediately. This action requires an `admin`-scoped API key.

**Path parameter:**

<ParamField path="id" type="string" required>
  The ID of the user to remove, prefixed with `usr_`.
</ParamField>

**Query parameter:**

<ParamField query="workspace_id" type="string" required>
  The ID of the workspace to remove the user from.
</ParamField>

```bash
curl -X DELETE "https://api.envoy.com/v1/users/usr_09ABZ1M2Q?workspace_id=ws_01HXZ3K9P" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

A successful deletion returns HTTP `204 No Content` with an empty body.

## Integrations

The Integrations endpoints let you list, connect, and disconnect third-party integrations for a workspace. Integration operations require a `write` or `admin`-scoped API key for write actions.

### GET /integrations

Retrieve a list of integrations connected to a workspace.

**Query parameters:**

<ParamField query="workspace_id" type="string" required>
  The ID of the workspace whose integrations you want to list.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Number of records to return. Maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned by a previous response. Omit on the first request.
</ParamField>

```bash
curl "https://api.envoy.com/v1/integrations?workspace_id=ws_01HXZ3K9P" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response:**

```json
{
  "data": [
    {
      "id": "int_04CKY8S6U",
      "workspace_id": "ws_01HXZ3K9P",
      "provider": "slack",
      "status": "connected",
      "connected_at": "2024-06-02T11:00:00Z"
    }
  ],
  "meta": {
    "total": 1,
    "limit": 20,
    "next_cursor": null
  }
}
```

### POST /integrations

Connect a new integration to a workspace.

**Request parameters:**

<ParamField body="workspace_id" type="string" required>
  The ID of the workspace to connect the integration to.
</ParamField>

<ParamField body="provider" type="string" required>
  The identifier for the integration provider (for example, `"slack"` or `"github"`).
</ParamField>

<ParamField body="config" type="object">
  Provider-specific configuration object. Refer to each provider's documentation for the expected fields.
</ParamField>

```bash
curl -X POST https://api.envoy.com/v1/integrations \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"workspace_id": "ws_01HXZ3K9P", "provider": "slack", "config": {}}'
```

**Example response:**

```json
{
  "data": {
    "id": "int_04CKY8S6U",
    "workspace_id": "ws_01HXZ3K9P",
    "provider": "slack",
    "status": "connected",
    "connected_at": "2024-06-02T11:00:00Z"
  }
}
```

### DELETE /integrations/:id

Disconnect an integration from a workspace. This immediately stops all data exchange with the connected provider.

**Path parameter:**

<ParamField path="id" type="string" required>
  The ID of the integration to disconnect, prefixed with `int_`.
</ParamField>

```bash
curl -X DELETE https://api.envoy.com/v1/integrations/int_04CKY8S6U \
  -H "Authorization: Bearer YOUR_API_KEY"
```

A successful deletion returns HTTP `204 No Content` with an empty body.

## Reports

The Reports endpoint allows you to fetch pre-built analytics reports for your workspaces. Reports are generated asynchronously; when a report is ready, Envoy fires a `report.ready` webhook event if you have one registered.

### GET /reports

Retrieve a list of available reports, optionally filtered by format or time range.

**Query parameters:**

<ParamField query="format" type="string" default="json">
  The format of the report data. Accepted values: `"json"`, `"csv"`.
</ParamField>

<ParamField query="range" type="string" default="30d">
  The time range for the report. Accepted values: `"7d"`, `"30d"`, `"90d"`, `"custom"`. When using `"custom"`, also provide `start_date` and `end_date` query parameters in `YYYY-MM-DD` format.
</ParamField>

<ParamField query="workspace_id" type="string">
  Limit results to reports for a specific workspace. If omitted, reports for all accessible workspaces are returned.
</ParamField>

```bash
curl "https://api.envoy.com/v1/reports?format=json&range=30d&workspace_id=ws_01HXZ3K9P" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

**Example response:**

```json
{
  "data": [
    {
      "id": "rpt_77CCX9Z1A",
      "workspace_id": "ws_01HXZ3K9P",
      "format": "json",
      "range": "30d",
      "status": "ready",
      "download_url": "https://api.envoy.com/v1/reports/rpt_77CCX9Z1A/download",
      "generated_at": "2024-06-03T06:00:00Z"
    }
  ],
  "meta": {
    "total": 1,
    "limit": 20,
    "next_cursor": null
  }
}
```

<Note>
  Report `download_url` values are pre-signed and expire after **15 minutes**. If a URL has expired, call `GET /reports` again to receive a fresh link.
</Note>

## Error Responses

All endpoints use standard HTTP status codes. When an error occurs, the response body contains an `error` object with a machine-readable `code` and a human-readable `message`.

| Status | Code                  | Description                                                                          |
|--------|-----------------------|--------------------------------------------------------------------------------------|
| `400`  | `bad_request`         | The request is malformed or missing required parameters. Check your request body and query parameters. |
| `401`  | `unauthorized`        | The API key is missing or invalid. Verify your `Authorization` header.               |
| `403`  | `forbidden`           | The API key lacks the required scope for this operation. Use a key with a higher scope. |
| `404`  | `not_found`           | The requested resource does not exist. Double-check the ID in your request.          |
| `409`  | `conflict`            | A resource with the same unique identifier already exists (for example, a duplicate workspace slug). |
| `422`  | `unprocessable`       | The request is well-formed but contains invalid field values. Review the `message` field for details. |
| `429`  | `rate_limit_exceeded` | You have exceeded your plan's request-per-minute limit. Wait for the `Retry-After` period before retrying. |
| `500`  | `internal_error`      | An unexpected error occurred on Envoy's servers. If the issue persists, contact support. |

**Example error response:**

```json
{
  "error": {
    "code": "not_found",
    "message": "Workspace ws_XXXXXXXX does not exist or you do not have access."
  }
}
```
