Every request to the Envoy API must be authenticated. Envoy uses API keys passed as Bearer tokens in the `Authorization` header. There are no cookies, sessions, or OAuth flows required for server-to-server communication — just a single header added to each request. Keep your keys secure and rotate them regularly to maintain a strong security posture.

## Generating an API Key

You can create an API key directly from the Envoy dashboard:

1. Navigate to **Settings → API Keys**.
2. Click **New Key**.
3. Give the key a descriptive name (for example, `production-integration` or `ci-deploy-bot`).
4. Select the appropriate **scope** (see [API Key Scopes](#api-key-scopes) below).
5. Click **Create** and copy the key immediately — it is only shown once.

<Warning>
  Envoy does not store your API key in plaintext. If you lose a key, you must revoke it and generate a new one. There is no way to retrieve an existing key after it has been created.
</Warning>

## Using Your API Key

Pass your API key in the `Authorization` header as a Bearer token on every request. The header format is:

```http
Authorization: Bearer YOUR_API_KEY
```

The following examples show how to attach your key across common HTTP clients:

<CodeGroup>

```bash curl
curl https://api.envoy.com/v1/workspaces \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```python Python
import requests

headers = {"Authorization": "Bearer YOUR_API_KEY"}
response = requests.get("https://api.envoy.com/v1/workspaces", headers=headers)
print(response.json())
```

```javascript JavaScript
const response = await fetch("https://api.envoy.com/v1/workspaces", {
  headers: { "Authorization": "Bearer YOUR_API_KEY" }
});
const data = await response.json();
```

</CodeGroup>

## API Key Scopes

When creating a key, you assign it one of three scopes. Choose the most restrictive scope that satisfies your use case to limit the blast radius of a compromised key.

| Scope   | Access Level                                                                 |
|---------|------------------------------------------------------------------------------|
| `read`  | Read-only access. Can call all `GET` endpoints but cannot create or modify resources. |
| `write` | Read and write access. Can call `GET`, `POST`, and `DELETE` endpoints for most resources. |
| `admin` | Full access, including user management, workspace deletion, and webhook configuration. |

<Tip>
  For external integrations that only need to pull data — such as a reporting dashboard — use a `read`-scoped key. Reserve `admin`-scoped keys for internal automation and protect them accordingly.
</Tip>

## Key Rotation Best Practices

Rotating API keys regularly reduces the risk of unauthorized access from leaked credentials. Follow these guidelines:

- **Rotate on a schedule.** Treat API keys like passwords and rotate them at least every 90 days.
- **Rotate immediately after exposure.** If a key is ever logged, committed, or shared accidentally, revoke it right away from **Settings → API Keys**.
- **Use separate keys per environment.** Maintain distinct keys for development, staging, and production so that rotating one does not affect another.
- **Use separate keys per service.** Assigning one key per integration or service makes it easy to revoke access for a single consumer without disrupting others.

<Warning>
  **Never commit API keys to source control.** Store keys in environment variables or a secrets manager such as AWS Secrets Manager, HashiCorp Vault, or your CI/CD platform's secret storage. Scanning tools like `git-secrets` or GitHub's secret scanning can help catch accidental commits, but prevention is far safer than detection.
</Warning>

## Authentication Error Responses

If authentication fails, the API returns one of the following errors:

| Status | Code            | Meaning                                                              |
|--------|-----------------|----------------------------------------------------------------------|
| `401`  | `unauthorized`  | The `Authorization` header is missing or the API key is invalid.    |
| `403`  | `forbidden`     | The API key is valid but does not have the required scope for this action. |

**Example 401 response:**

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing API key."
  }
}
```

**Example 403 response:**

```json
{
  "error": {
    "code": "forbidden",
    "message": "Your API key does not have permission to perform this action."
  }
}
```
