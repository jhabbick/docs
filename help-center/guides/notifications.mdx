Envoy can alert you and your team whenever something important happens — a new member joins, a security event is detected, a bill is due, or a system update is rolling out. You control exactly where those alerts go and how often you receive them, down to the individual event category.

## Notification types

Envoy delivers notifications through four channels:

- **Email** — Sent to the address on your Envoy account. Supports real-time delivery or a daily digest.
- **In-app** — Appears in the notification bell (🔔) in the top-right corner of the Envoy dashboard while you're logged in.
- **Slack** — Posted to one or more Slack channels you specify. Requires the [Slack integration](/help-center/guides/first-integration) to be connected first.
- **Webhook** — Sends an HTTP POST request to a URL you control whenever a subscribed event fires. Ideal for custom automations and third-party pipelines.

## Notification categories

Every notification belongs to one of four categories. You can enable or disable each category independently per channel:

| Category | Examples |
|----------|---------|
| **Activity** | Member invited, record created or updated, integration connected |
| **Security** | Failed login attempt, API key created or revoked, SSO configuration changed |
| **Billing** | Invoice generated, payment failed, plan upgraded or downgraded |
| **System** | Scheduled maintenance, feature deprecation notices, outage updates |

## Configure notifications by channel

<Tabs>
  <Tab title="Email Notifications">
    ### Set your email preferences

    1. Go to **Settings → Notifications**.
    2. Under **Email**, toggle on the categories you want to receive.
    3. Choose your delivery mode:
       - **Real-time** — Envoy sends an email immediately when an event occurs.
       - **Daily Digest** — Envoy batches all notifications from the past 24 hours into a single summary email, delivered at 8:00 AM in your local timezone.
    4. Click **Save Preferences**.

    Email notifications go to the address associated with your Envoy account. To update that address, go to **Settings → Profile → Email Address**.

    <Note>
      Billing notifications are always sent in real-time regardless of your digest setting — you won't miss a failed payment because of a batching preference.
    </Note>
  </Tab>
  <Tab title="Slack Notifications">
    ### Connect Slack and configure channels

    Before you can route notifications to Slack, connect your Slack workspace via **Settings → Integrations → Slack**. See [Connect Your First Integration](/help-center/guides/first-integration) for step-by-step instructions.

    Once Slack is connected:

    1. Go to **Settings → Notifications**.
    2. Under **Slack**, click **Configure Channels**.
    3. For each notification category, select the Slack channel where those notifications should appear. You can route different categories to different channels — for example:
       - **Activity** → `#envoy-activity`
       - **Security** → `#security-alerts`
       - **Billing** → `#finance-ops`
       - **System** → `#engineering`
    4. Click **Save Channel Mappings**.

    To stop sending a category to Slack, set its channel to **None**.
  </Tab>
  <Tab title="Webhook Notifications">
    ### Set up a webhook endpoint

    1. Go to **Settings → Notifications → Webhooks**.
    2. Click **Add Webhook**.
    3. Enter the URL of your endpoint — it must be publicly reachable and accept `POST` requests.
    4. Select the event categories you want to subscribe to.
    5. Optionally, add a **Secret** to sign webhook payloads. Envoy includes an `X-Envoy-Signature` header so your server can verify authenticity.
    6. Click **Save Webhook**.

    Envoy retries failed webhook deliveries up to five times with exponential backoff before marking the event as undelivered.

    ### Webhook payload format

    Every webhook POST includes a JSON body with the following structure:

    ```json
    {
      "event": "member.invited",
      "timestamp": "2024-06-01T14:22:00Z",
      "workspace_id": "ws_01HXZ3K9P",
      "data": {
        "email": "alice@example.com",
        "role": "member",
        "invited_by": "bob@example.com"
      }
    }
    ```

    The `event` field uses dot notation in the format `category.action` (for example, `security.login_failed` or `billing.payment_failed`). The `data` object contains event-specific fields that vary by event type.
  </Tab>
</Tabs>

## Mute notifications

To temporarily silence notifications without changing your preferences:

1. Click the notification bell (🔔) in the top-right corner of the dashboard.
2. Click **Mute Notifications**.
3. Choose a mute duration: **1 hour**, **8 hours**, **24 hours**, or **Until I unmute**.

Muting suppresses in-app and email notifications only. Webhook deliveries continue unaffected so your downstream automations keep running.

<Tip>
  **Best practice:** Route Security notifications to both email (real-time) and a dedicated Slack channel so your team has immediate visibility into potential issues — even when individuals are away from their inboxes. For Billing notifications, add at least two Admins as recipients so a single person's absence never causes a missed payment alert.
</Tip>
